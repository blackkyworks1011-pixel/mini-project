## 1. Abstract
The Library Management System is a menu-driven C++17 console application intended to simplify basic library operations. It supports book catalogue maintenance, student registration, issuing and returning books, active-loan tracking, and calculation of overdue fines. Records are stored in CSV files so that information remains available after the application is closed and reopened.

## 2. Problem Statement
Maintaining book and borrower records manually can make it difficult to find books, identify currently issued items, and keep issue/return information consistent. This project provides a small computerized solution for these routine operations.

## 3. Objectives
- Maintain a catalogue of books.
- Register student borrowers.
- Search books by title or author.
- Issue available books to registered students.
- Record returns and calculate overdue fines.
- Persist records between application sessions.
- Demonstrate object-oriented programming, STL, file handling, and exception handling in C++.

## 4. Scope
The application is designed for a small academic demonstration. It uses a local CSV-file store and a console menu. It does not provide network access, concurrent multi-user operation, authentication, or a graphical user interface.

## 5. Software and Hardware Requirements
**Software:** C++17 compiler (GCC, Clang, or Visual Studio), terminal, and optionally CMake and Git.  
**Hardware:** A computer capable of running a modern C++ compiler; no special hardware is required.

## 6. Functional Modules
1. **Book management:** Add, list, search, and remove books.
2. **Student management:** Register and list students.
3. **Issue management:** Issue an available book to a registered student.
4. **Return management:** Return a book, close its active loan, and calculate any overdue fine.
5. **Persistence:** Read and write books, students, and loans using CSV files.

## 7. OOP and C++ Concepts
- **Encapsulation:** Book data is private and accessed through public member functions.
- **Inheritance:** `Student` derives from the abstract `Person` class.
- **Abstraction:** `Person` declares the pure virtual `getRole()` operation.
- **Runtime polymorphism:** `Student` overrides `getRole()`.
- **STL:** `vector` stores books and loans; `map` stores students; algorithms such as `find_if`, `replace`, and `transform` support searching and validation.
- **Exception handling:** `LibraryException` provides application-specific error reporting; `try`/`catch` protects menu operations.
- **File handling:** `ifstream` and `ofstream` load and save CSV records.

## 8. Data Design
- `books.csv`: book ID, title, author, category, availability.
- `students.csv`: student ID, name, department.
- `loans.csv`: book ID, student ID, issue timestamp.

The application expects to be launched from the project root, where the `data/` directory is present.

## 9. Business Rules
- Book IDs and student IDs must be unique.
- A book must exist and be available before it can be issued.
- A borrower must be registered before borrowing.
- A book can have only one active loan.
- A book must be returned before it can be removed.
- The demonstration loan period is 14 days; the overdue fine is Rs. 5 per day after that period.

## 10. Build and Execution
### With GCC
```bash
g++ -std=c++17 -Wall -Wextra -pedantic src/main.cpp -o library
./library
```

### With CMake
```bash
cmake -S . -B build
cmake --build build
./build/library
```
On Windows, run `build\\Debug\\library.exe` or the executable path generated by your CMake toolchain.

## 11. Test Plan
